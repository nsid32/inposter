# Decisions

Locked architectural and product decisions. Never contradict one; if one seems wrong, say so
and amend it here, dated, rather than working around it. A superseded decision says
**Superseded by D-NN** and stays, as history.

These were not written when they were made. Each is recorded from the code and the project's own
documents on 2026-10-21; the date it was actually decided is unknown unless stated. The owner
should confirm each.

## D-01 — Next.js App Router, React and TypeScript in one app

**Decided:** recorded from the code on 2026-10-21

One Next.js App Router app under `src/`: pages in `src/app/*/page.tsx` as client components,
route handlers in `src/app/api/**/route.ts`, shared code in `src/lib/`, path alias `@/*` to
`src/*`. TypeScript `strict`. React 18. `next` is `16.2.4` since the Dependabot bump in 0.4.4
(2026-04-19); README and CLAUDE.md still say Next.js 14 and `eslint-config-next` is `14.2.29`.
One process serves UI and routes, which suits a local single-user tool. Revisit if the app ever
needs to run as something other than a local web app (a desktop wrapper, for example).

## D-02 — Local-first, single user, no sign-in, no hosting

**Decided:** recorded from `CLAUDE.md` and `CONTRIBUTING.md` on 2026-10-21

InPoster runs on the user's own machine via `./scripts/run.sh`, which starts the Next.js dev
server on port 3000. There is no production build in use, no hosting, no multi-tenancy and no
authentication: whoever can reach the app is its user. Features that need a hosted backend are
out of scope. Cost: no access from other devices, and no protection if the port is reachable from
the network (see the open point in `docs/tech/CODEMAP.md`, "Gaps"). Revisit if the owner wants
InPoster to serve people who cannot run it themselves, or if binding to localhost only is
decided.

## D-03 — SQLite through Drizzle ORM and better-sqlite3

**Decided:** recorded from the code on 2026-10-21

All data is in one SQLite file, `data/inposter.db` (gitignored), opened in `src/lib/db/index.ts`
with `better-sqlite3` in WAL mode and wrapped by Drizzle (`drizzle-orm/better-sqlite3`). Schema
in `src/lib/db/schema.ts`; migrations generated by `drizzle-kit` into `drizzle/` and applied by
`npm run db:migrate`, which `scripts/setup.sh` and `scripts/run.sh` both run. Queries are
synchronous (`.get()`, `.all()`, `.run()`). Timestamps are ISO 8601 strings in `text` columns.
`better-sqlite3` is a webpack server external (`next.config.mjs`). Revisit only with D-02.

## D-04 — Pictures are files on disk, referenced from the post

**Decided:** recorded from the code on 2026-10-21 (CHANGELOG 0.4.2, "image storage")

A post has at most one picture, stored as `data/images/post-<id>-<timestamp>.<ext>` with the
relative path in `posts.image_path` and the type in `posts.image_mime_type`. Pictures travel
between browser and server as base64 in JSON. The earlier design kept base64 in
`posts.image_data`; that column is legacy, read only as a fallback, and moved to files by
`migrateImagesToFiles()` (`src/lib/migrateImages.ts`). Allowed types JPEG, PNG, GIF, WebP;
5 MB.

## D-05 — Access keys encrypted at rest with a local key

**Decided:** recorded from the code on 2026-10-21

The keys in `SENSITIVE_KEYS` (`anthropic_api_key`, `make_webhook_api_key`, `openai_api_key`,
`unsplash_access_key`) are stored in `settings` with `encrypted = 1`, AES-256-GCM, key derived
with scrypt from `ENCRYPTION_KEY` in `.env.local` (fallback: the machine's hostname, with a
warning). `scripts/setup.sh` generates `ENCRYPTION_KEY` once, never regenerates it, and
re-encrypts values stored under the hostname key. `GET /api/settings` returns them masked; the
browser never receives a stored key. Losing `.env.local` makes stored keys unreadable; the user
re-enters them.

## D-06 — Publish to LinkedIn only through the user's Make.com scenario

**Decided:** recorded from `CLAUDE.md` and backlog F0018 on 2026-10-21

InPoster never talks to LinkedIn. Publishing posts JSON to the user's Make.com webhook URL
(`make_webhook_url`, optional `x-make-apikey` header), and the user's scenario posts to LinkedIn.
A direct LinkedIn OAuth integration with post sync was built (F0003) and removed (F0018) because
LinkedIn restricts the needed product to a standalone app. **The payload is a contract with
users' scenarios:** `post_id`, `content`, `tone`, `published_at`, and with a picture
`image_data` (base64), `image_mime_type`, `image_extension`. Adding fields is safe; renaming or
removing one breaks every existing scenario, and README's Make.com guide maps them by name. A post
becomes `published` when Make.com answers 2xx; InPoster cannot know whether LinkedIn accepted it.

## D-07 — Bring-your-own-key AI and photo services

**Decided:** recorded from the code on 2026-10-21

Text: Anthropic Claude through `@anthropic-ai/sdk`, model chosen in Settings (`claude_model`:
`claude-sonnet-4-6` default, `claude-haiku-4-5-20251001`). Pictures: OpenAI DALL-E 3 through
`openai`. Stock photos: Unsplash, through `fetch`. Each uses the user's own key from settings; all
calls are made server-side from route handlers. Prompts ask the model for JSON only, and the
routes strip code fences and `JSON.parse` the text. Only Anthropic is required; OpenAI and
Unsplash features are disabled in the UI without their keys.

## D-08 — UI kit: Tailwind CSS, shadcn/ui, dark by default

**Decided:** recorded from the code on 2026-10-21

Tailwind CSS 3 with `tailwindcss-animate`, shadcn/ui components (Radix) in `src/components/ui/`,
lucide-react icons, sonner toasts. Dark theme by default, light theme by the `dark` class on
`<html>`, chosen with the `theme` cookie (read in the root layout) and mirrored to the `theme`
setting.

## D-09 — Releases by the owner from Conventional Commits

**Decided:** recorded from `CLAUDE.md`, `README.md` and `scripts/release.sh` on 2026-10-21

Commits follow Conventional Commits. `./scripts/release.sh` derives the semver bump (`feat` minor,
`fix` patch, `BREAKING CHANGE` major), updates `CHANGELOG.md` and `package.json`, commits, tags and
pushes. Only the owner runs it; agents never push. The version shown in the sidebar comes from
`package.json`.
